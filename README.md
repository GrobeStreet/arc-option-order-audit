# ARC-Challenge option-order robustness audit

An independent, reproducible check of one question: **does a small language model's score on ARC-Challenge depend on the
order in which the answer options are shown, and does that shrink as the model gets bigger?**

Every question is shown four times with its options cyclically rotated (A-B-C-D, B-C-D-A, ...). Scoring uses the model's
next-token logits over the labels A-D after a raw-completion prompt (no chat template). Model revisions, dataset revision
and seed are pinned. Every number in `RESULTS.md` is generated by code from the raw per-prediction files in this repo;
none are typed by hand. Both models see the same 1,165 questions (all four-option items in the ARC-Challenge test split),
4,660 predictions each.

## Headline results

| | Qwen2.5-0.5B-Instruct | Qwen2.5-1.5B-Instruct |
|---|---|---|
| Mean accuracy over the four orderings | 48.7% (46.7 to 50.8) | 74.5% (72.4 to 76.7) |
| Questions whose chosen answer changes with option order | **74.6%** (72.1 to 77.2) | **31.6%** (28.8 to 34.2) |
| Correct under all four orderings | 19.1% | 60.4% |
| Accuracy when the correct answer is in slot A / B / C / D | 52.7 / 60.3 / 55.9 / **26.0** | 69.2 / 74.8 / 79.1 / 75.1 |
| Share of picks landing on slot D | 11.9% | 26.4% |

Intervals are 95% bootstrap intervals over questions.

1. **A single-ordering score hides the bias.** For both models, accuracy per rotation is nearly identical, because cycling
   the options puts the correct answer in each slot equally often and slot bias cancels in the average. The bias shows up
   in the flip rate and in accuracy-by-slot.
2. **The 0.5B model has a large slot bias.** It is 26.0% accurate when the correct answer sits in slot D (about chance)
   but 60.3% when it sits in slot B (chi-square p < 1e-70), and it picks D only 11.9% of the time.
3. **It shrinks a lot with size but does not disappear.** The 1.5B model flips on 31.6% of questions instead of 74.6%, and
   its slot dependence is much smaller but still detectable (accuracy 69.2% in slot A versus 79.1% in slot C; chi-square
   p ≈ 9e-7). This is two model sizes from one family, so it is not a scaling law.
4. **Flips are not pure noise.** A model that ignored content and picked slots by its observed slot preferences would flip
   on about 98.5% of questions. Accuracy on the flipping questions is 39.8% (0.5B) and 44.7% (1.5B), above the 25% chance
   floor. The "stable" questions are more accurate (75.0% and 88.3%), but that subset is selected by being stable, so it
   should not be read as the model's ability on easy items.

## Limits (please read)
- Two small models from one family, one fixed prompt template, label-logit scoring rather than free-text generation.
  This says nothing about frontier models.
- Four cyclic rotations, not all 24 permutations. Option order only; no paraphrase or other perturbations.
- Seven of 1,172 ARC-Challenge test questions do not have exactly four options and are excluded.
- **Precision differs between the two models.** The 0.5B model ran in float32. The 1.5B model ran in bfloat16 because float32
  runs out of memory on the 8 GB CPU machine used. bfloat16 produced 60 exact probability ties (1.3% of predictions), which
  the harness breaks by slot order. A control that re-decides every tie at random (`tie_control.py`, 200 reseeds) moves the
  1.5B accuracy by at most 0.3 point and the flip rate from 31.6% to 32.1% (range 31.6 to 32.7), so ties do not drive the result.
  The two models are not matched on precision, so the size comparison is confounded to that extent.
- The 1.5B run was resumed from checkpoints after container restarts. Each question is scored independently with fixed
  weights, so resuming does not change any prediction, but the provenance file reflects the final invocation.
- Not peer reviewed. Different hardware can change the last digits; provenance files record package versions and the SHA-256
  of each raw results file.

## Reproduce
```
pip install -r requirements.txt
python audit.py --model Qwen/Qwen2.5-0.5B-Instruct --out results_qwen2.5-0.5b.parquet                    # ~45 min, 2 CPU cores
python audit.py --model Qwen/Qwen2.5-1.5B-Instruct --dtype bfloat16 --out results_qwen2.5-1.5b.parquet   # ~40 min
python analyze.py results_qwen2.5-0.5b.parquet --out summary_qwen2.5-0.5b.json
python analyze.py results_qwen2.5-1.5b.parquet --out summary_qwen2.5-1.5b.json
python tie_control.py results_qwen2.5-1.5b.parquet
python make_report.py                                                                                      # writes RESULTS.md
```

## Files
`audit.py` (run the model; checkpoints and resumes) · `analyze.py` (all statistics, bootstrap over questions, baselines) ·
`tie_control.py` · `make_report.py` · `results_*.parquet` (raw predictions) · `summary_*.json` · `RESULTS.md`.
