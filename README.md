# ARC-Challenge option-order robustness audit

An independent, reproducible check of one question: **does a small language model's score on ARC-Challenge depend on the
order in which the answer options are shown, and how does that vary across model size and family?**

Every question is shown four times with its options cyclically rotated (A-B-C-D, B-C-D-A, ...). Scoring uses the model's
next-token logits over the labels A-D after a raw-completion prompt (no chat template). Model revisions, dataset revision
and seed are pinned. Every number in `RESULTS.md` is generated by code from the raw per-prediction files in this repo;
none are typed by hand. All models see the same 1,165 questions (all four-option items in the ARC-Challenge test split),
4,660 predictions each. Four models from two families: Qwen2.5 (0.5B, 1.5B) and SmolLM2 (360M, 1.7B).

## Headline results

| | Qwen2.5-0.5B | Qwen2.5-1.5B | SmolLM2-1.7B | SmolLM2-360M |
|---|---|---|---|---|
| Mean accuracy over the four orderings | 48.7% (46.7 to 50.8) | 74.5% (72.4 to 76.7) | 58.2% (56.1 to 60.3) | 24.9% (24.5 to 25.2) |
| Questions whose chosen answer changes with option order | **74.6%** (72.1 to 77.2) | **31.6%** (28.8 to 34.2) | **59.8%** (56.9 to 62.6) | 100.0% |
| Correct under all four orderings | 19.1% | 60.4% | 33.6% | 0.0% |
| Accuracy when the correct answer is in slot A / B / C / D | 52.7 / 60.3 / 55.9 / **26.0** | 69.2 / 74.8 / 79.1 / 75.1 | 58.3 / 55.9 / 58.2 / 60.3 | 8.6 / 0.3 / 84.3 / 6.3 |
| Slot dependence of correctness (chi-square p) | 4.6e-72 | 9.2e-7 | 0.19 | ~0 |
| Precision used | float32 | bfloat16 | bfloat16 | float32 |

Intervals are 95% bootstrap intervals over questions.

1. **A single-ordering score hides the bias.** For every model, accuracy per rotation is nearly identical, because cycling
   the options puts the correct answer in each slot equally often and slot bias cancels in the average. The bias shows up
   in the flip rate and in accuracy-by-slot.
2. **The Qwen2.5-0.5B model has a large slot bias.** It is 26.0% accurate when the correct answer sits in slot D (about
   chance) but 60.3% when it sits in slot B (chi-square p < 1e-70), and it picks D only 11.9% of the time.
3. **Within Qwen, the effect shrinks a lot with size but does not disappear.** The 1.5B model flips on 31.6% of questions
   instead of 74.6%, and its slot dependence is much smaller but still detectable (accuracy 69.2% in slot A versus 79.1% in
   slot C; p ≈ 9e-7).
4. **Across families, size does not predict the flip rate.** SmolLM2-1.7B is about the same size as Qwen2.5-1.5B but flips
   on 59.8% of questions versus 31.6%. It is also less accurate (58.2% versus 74.5%), so family, accuracy and size are
   entangled here; this is four models, not a scaling law. Its instability does not look like a simple slot preference:
   its picks are spread almost evenly over A-D (26.8 / 22.9 / 23.2 / 27.0%) and its accuracy by correct-answer slot is flat
   (p = 0.19), yet 59.8% of its answers still change with order.
5. **SmolLM2-360M carries no signal on this task.** It scores at chance (24.9%) and picks slot C 85% of the time, so its
   100% flip rate is a floor effect, not evidence about robustness. It is included for completeness and should not be used
   in comparisons.
6. **Flips are not pure noise.** A model that ignored content and picked slots by its observed slot preferences would flip
   on about 98.5% of questions. Accuracy on the flipping questions is 39.8% (Qwen 0.5B), 44.7% (Qwen 1.5B) and 41.1%
   (SmolLM2-1.7B), above the 25% chance floor. The "stable" questions are more accurate (75.0%, 88.3%, 83.5%), but that
   subset is selected by being stable, so it should not be read as the model's ability on easy items.

## Limits (please read)
- Four small models from two families, one fixed prompt template, label-logit scoring rather than free-text generation.
  This says nothing about frontier models.
- Four cyclic rotations, not all 24 permutations. Option order only; no paraphrase or other perturbations.
- Seven of 1,172 ARC-Challenge test questions do not have exactly four options and are excluded.
- **Precision differs across models.** The 0.5B and 360M models ran in float32. The 1.5B and 1.7B models ran in bfloat16
  because float32 runs out of memory on the 8 GB CPU machine used. bfloat16 produced exact probability ties (60 for Qwen 1.5B,
  1.3% of predictions; 121 for SmolLM2-1.7B, 2.6%), which the harness breaks by slot order. A control that re-decides every
  tie at random (`tie_control.py`, 200 reseeds) moves accuracy by at most 0.3 point and the flip rate from 31.6% to 32.1% (Qwen
  1.5B) and from 59.8% to 60.3% (SmolLM2-1.7B), so ties do not drive the results. Because precision is confounded with
  size in this design, size comparisons carry that caveat.
- Runs were executed in resumable chunks (checkpointed every five questions) after container restarts. Each question is scored
  independently with fixed weights, so resuming does not change any prediction, but each provenance file reflects the final
  invocation.
- Not peer reviewed. Different hardware can change the last digits; provenance files record package versions and the SHA-256
  of each raw results file.

## Reproduce
```
pip install -r requirements.txt
python audit.py --model Qwen/Qwen2.5-0.5B-Instruct --out results_qwen2.5-0.5b.parquet                              # ~45 min, 2 CPU cores
python audit.py --model Qwen/Qwen2.5-1.5B-Instruct --dtype bfloat16 --out results_qwen2.5-1.5b.parquet             # ~40 min
python audit.py --model HuggingFaceTB/SmolLM2-360M-Instruct --out results_smollm2-360m.parquet                    # ~40 min
python audit.py --model HuggingFaceTB/SmolLM2-1.7B-Instruct --dtype bfloat16 --out results_smollm2-1.7b.parquet   # ~50 min
for m in qwen2.5-0.5b qwen2.5-1.5b smollm2-360m smollm2-1.7b; do python analyze.py results_$m.parquet --out summary_$m.json; done
python tie_control.py results_qwen2.5-1.5b.parquet
python tie_control.py results_smollm2-1.7b.parquet
python make_report.py                                                                                                # writes RESULTS.md
```

## Files
`audit.py` (run the model; checkpoints and resumes) · `analyze.py` (all statistics, bootstrap over questions, baselines) ·
`tie_control.py` · `make_report.py` · `results_*.parquet` (raw predictions) · `summary_*.json` · `RESULTS.md`.
